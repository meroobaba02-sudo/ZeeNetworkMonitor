# Zee Network Monitor v0.5.1 — Discovery and measured alignment

This upgrade extends the existing Python/PySide6 NOC application. The current GUI, live ping, device/tower/page management, WAN tests, alarms, history, credential vault and licensing checks are preserved. No schema migration or example devices are added. First-version startup and discovery import use the existing SQLite backup mechanism; complete-folder backups retain credential/mobile/licence sidecars.

## Beginner launch

1. Download the successful Windows build's Setup artifact, extract the ZIP and run `ZeeNetworkMonitor-Setup-Windows-v0.5.1.exe`. Python and Qt are packaged. Existing saved data remains in its existing data directory.
2. Alternatively extract the portable artifact, then extract its inner portable ZIP. Run `ZeeNetworkMonitor.exe` from the extracted folder. Keep `_internal` and all other files beside it; do not launch inside a ZIP or copy the EXE alone.
3. Open Network Discovery or Dish Alignment from the existing sidebar. Normal monitoring remains available independently.

## Automatic adapter detection and discovery

Connected Windows IPv4 interfaces and preferred addresses are detected asynchronously at startup. The page lists adapter name, address, mask and connected subnet. A short 60-second in-process cache avoids launching PowerShell for every dialog/test; Refresh adapters forces a new read. Selecting an adapter fills its subnet and binds the scan to that source IP without changing the network page, Windows IP settings, routes or gateways. Large connected subnets are shown accurately, but must be narrowed to at most 1,024 addresses before scanning. Development-host loopback inventory is labelled as such; it is not a user's Windows inventory.

1. Select your actual adapter or use the existing network page's configured source. Enter a CIDR subnet (such as your own `/24`) or an inclusive `start-end` IPv4 range.
2. Tick the exact-range ownership/permission checkbox. Start Scan, Stop Scan and Rescan are explicit controls. If the range is remote, public/third-party, outside the detected source subnet, or its local scope cannot be established, a separate confirmation names the exact range and source. Authorization is session-only, never inferred from private IP space or saved station presets. Scope/method changes revoke it. Scans stop replenishing immediately on Stop; at most four bounded in-flight checks finish.
3. Defaults: ICMP, four workers maximum, eight host starts per second; adjustable 1–20 starts/sec and 100–2,000 ms per ping/TCP timeout. Windows system ping may have its existing process deadline overhead. Optional DNS PTR is off by default and bounded at two seconds. Optional TCP connects are off by default, limited to three specified ports (80/443 initially), and send no application payload, authentication, banner request or configuration change.
4. Results show IP, MAC, hostname, vendor, response time, discovery method and check time. Filter and Export CSV act on displayed results. Select rows and Add Selected Devices; a pre-import SQLite backup is made, additions occur in four-record UI batches, and exact IP/source duplicates in the page are skipped. Identified-only devices may be added with their reachability unconfirmed; importing never turns them into synthetic online readings.
5. Save remote station keeps a named range, source and network page separately from local adapter detection. Select its original network page/source before using the preset. Saving a preset grants no scanning permission.
6. Optional rediscovery repeats the exact authorized scope every 1–60 minutes during this session, only after an explicit successful Start authorization. It never imports devices automatically. Changing scope/page/source, revoking permission, pressing Stop or closing the application stops repetition. It is off at every new launch.

### Evidence rules

- ICMP echo or an accepted TCP connection is response evidence. A successful TCP-only device can be found despite blocked ICMP. Response time identifies the method; TCP connect time is not ICMP latency.
- The Windows neighbour/ARP table is interface-scoped, only used on the selected direct subnet, and read again after scanning. A current Windows `Reachable` entry is recent ARP reachability evidence, not a fresh ICMP reply or exact RTT. Stale/static/cache-only entries identify an address/MAC but do not prove liveness. Ambiguous interface/MAC entries are omitted. There is no raw ARP flood and no elevation requirement.
- DNS PTR identifies a recorded name, even without ping. It does not prove the host is currently reachable. DNS/cache-only results explicitly say “Identified; reachability unconfirmed.” No supported response means “status unknown”, never offline solely due to ping failure. Existing monitoring continues to report its specific ICMP evidence.
- Vendor lookup uses an optional operator-supplied trusted IEEE-style CSV, up to 8 MB: `Assignment,Organization Name` or `prefix,vendor` columns; 24/28/36-bit longest-prefix matches. No OUI is guessed, fetched automatically or used to infer device type. Locally administered MACs and unmatched assignments remain unavailable. Load the CSV each session. Export escapes formula-leading text from network-supplied names.

## Rocket M5 and compatible-device alignment

The application reuses its existing read-only SNMP v1/v2c and explicit HTTPS JSON mapping adapters. Official airOS 6 documentation describes its SNMP agent and native antenna-alignment tool; this does **not** establish any universal JSON API, OID instance/index or firmware compatibility. Record the actual model/firmware, configure confirmed numeric OIDs/field mappings and scales, and mark the profile verified only after comparing it with that actual device. Existing Windows DPAPI credentials remain in the protected vault; credentials never enter discovery, saved alignment samples or logs. SNMP v1/v2c itself is unencrypted and still needs explicit trusted-management-network permission. HTTPS retains certificate validation and same-host credential enforcement.

1. Select the radio; radios with explicit signal mappings are also selectable. Configure telemetry, then Test telemetry to request an actual read. Unsupported, failed or stale metrics remain unavailable. Open device is the manual fallback; in airOS use Tools → Align Antenna. No guessed browser-login/API endpoint is called.
2. Start Alignment and leave the dish still for at least three **new** stable baseline samples. Polling uses the saved safe interval, minimum five seconds, with existing bounded workers. The page redraws once per second without sending one request per redraw.
3. Record a small LEFT/RIGHT/UP/DOWN move after physically adjusting. Optional amount/unit records your measurement (operator units, manually measured degrees, turns or millimetres). Each click creates a separate numbered step. Three or more stable measurements after the move are compared with the previous stable position; timestamps before the step/session are excluded. Repeated RIGHT moves remain separate and cannot be averaged into a misleading single direction.
4. The assistant reports before/after change, recent stability and best stable measured position. Stable step spread must be at most 2 dB, and a directional improvement must exceed a stable baseline by at least 1 dB. Keep/return to the best recorded position only if other link indicators are acceptable; the assistant does not know mechanical position or command a motor. There is no calibrated direction sensor supplied, so directions come only from your measured sweeps. No direction is guessed from RSSI, GPS coordinates or compass heading alone.
5. Noise, SNR, chain levels/imbalance, TX/RX CCQ, TX/RX rates and measured link quality are shown separately. RSSI alone never certifies perfect alignment. Target bearing/elevation are manual references. Verified numeric mappings can additionally supply GPS latitude/longitude, heading and elevation with validated units/bounds; absent sensors/data remain unavailable. No laptop compass/GPS driver is assumed.
6. Optional audio plays a short measured-improvement tone, with higher pitch for stronger RSSI on Windows. It runs in a separate one-worker pool, is throttled to at most once per five seconds, and stops scheduling on Pause/Finish/disable/close. Audio hardware is not verified remotely.
7. Pause, Reset Peak, Finish Alignment and Save Results operate on the measured session. Saved results include actual samples/metrics, numbered step comparisons, best stable reading and target references in the existing database. Latest 600 samples, latest 100 step descriptors and one saved result per device are retained; no simulated measurements are shipped. Reset Peak changes only the current peak marker, not saved samples or the stable-position comparison.

The screen includes a rooftop/electrical safety reminder: trained personnel, fall protection, safe weather, clearance from power lines and isolating electrical/PoE equipment before cable handling.

## Verification and remaining limits

Tests cover IPv4/range validation, connected inventory normalization, authorization denial/change/rediscovery, rate spacing, bounded cancellation, real local TCP connect without payload or ping, DNS identity versus reachability, fresh/stale/interface-scoped neighbour evidence, vendor CSV, filtered export, import backup/deduplication, repeated adjustments, timestamp exclusion, stable-best comparisons, stale metrics, verified GPS bounds, audio scheduling, telemetry test/web fallback and existing NOC navigation. Windows CI additionally checks native adapter/neighbour queries, the complete regression suite, frozen startup, packaging, installer launch/upgrade/uninstall and data preservation.

Fixtures and loopback servers are tests only. Your actual Windows laptop, remote routing/permissions, Rocket firmware/OIDs, sensor availability, physical adjustments and audio hardware still need field validation. ARP/MAC is unavailable across routers, DNS can be missing/stale and a firewall can block all methods while a device remains operational. At 1,024 addresses, scans may take minutes because of limits/timeouts and optional DNS/TCP. No automatic service fingerprinting, SNMP walk, raw ARP probing, vendor database download, Wi-Fi spectrum scan, automatic configuration writes or unverified Ubiquiti API is added. Existing routing requirements remain; the app does not create internal routes to otherwise inaccessible stations.
