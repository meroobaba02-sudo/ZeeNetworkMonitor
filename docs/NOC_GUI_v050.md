# Zee Network Monitor v0.5.0 — NOC GUI redesign

This is the existing Python/PySide6 Windows application, not a replacement engine. Existing device/tower records, pages, ICMP workers, WAN routing checks, credentials, retention, incidents, backups, mobile access and licence enforcement remain intact. Admin Studio/manager delivery stays paused. Current packages contain only Network Monitor; the normal unprovisioned owner preview still needs no activation.

## Screens

- Dashboard: twelve scoped cards for devices, online/unknown/warnings, configured WANs/peer links, fresh mean latency, sampled ICMP loss/uptime, active alerts, last-hour failed ping samples, unreachable devices and verified external Internet failures. All figures come from configured devices and actual stored/live observations. Latency excludes unavailable replies. Loss/uptime uses cached retained ICMP samples with coverage in its tooltip; this is not guaranteed service uptime. The overview keeps incident evidence, seven WAN summaries and device review actions.
- Internet Monitor: seven cards per page (extra connections paginate), router name/IP, fresh controlled test throughput separated from fresh verified interface usage, latency/loss/last reply, individual Start Test/Stop Test/Test Again/Setup, plus bounded timestamped download/upload history. Tests queue sequentially to avoid competing for bandwidth. Stop cancels only that connection/queued item. Detailed measurement table and existing batch/ping/counter/browser tools remain available.
- Network Discovery: explicit Start/Stop/Rescan, subnet validation capped at 1,024 IPv4 addresses, four probe workers, progress, result filter and multi-selection import. Optional Windows PTR hostname lookup is bounded and off by default. MAC is an unambiguous cached Windows neighbour entry; vendor remains unavailable without a verified OUI source. A reply does not identify device type, prove physical connectivity or guarantee Internet access. Import only selected responding devices into the scanned page; preserve prior devices, skip duplicates, and take a SQLite backup first. Scan/source changes require returning to the scanned network. In-flight calls finish within existing deadlines after Stop; no routes or device configuration are altered.
- Network Map: interactive configured-link schematic plus the preserved offline geographic tower map. Station groups/nodes come from saved records; parent/peer links are explicit. The Lahore–intermediate–Sargodha text is an editable operator reference label, not generated physical evidence. No demo stations/links are inserted. Click a device for details; click a station to manage its radios. Zoom, pan and Fit are supported. Map search highlights matching nodes while retaining dimmed context. Last observed reachable parent uses fresh ping states; red links are observed ICMP/critical radio evidence, never a confirmed physical break. The existing geographic map retains its Zhob/Sambaza data, downloads, tower placement and movement; Lahore/Sargodha roads are not automatically downloaded.
- Rocket M5 Monitor: actual configured radio cards, RSSI/noise/TX and RX rates/CCQ, detailed supported chain levels, signal history, connection test, adapter setup, web interface and alignment shortcut. Chain levels are supported through explicitly verified numeric SNMP/HTTPS field mappings; no firmware OIDs are guessed. Unsupported/stale data stays unavailable.
- Dish Alignment: large fresh RSSI meter, bounded session graph, peak/stability, optional improvement beep, Start/Pause/Reset Peak/Finish/Save Results, manual bearing/elevation reference fields and operator-tagged Baseline/LEFT/RIGHT/UP/DOWN adjustments. Direction suggestions need at least three baseline and three stable adjustment samples with >=1 dB median improvement. This compares a measured sweep; it is not a direction/angle sensor. With RSSI alone the screen explicitly reports direction unavailable. Finished measured sessions save in the existing SQLite settings and are included in database backup.
- Alerts & History, Device Manager and Settings: existing filtering, acknowledgements, notes, detailed ping history, device CRUD/station assignment, secure credentials, alert delay, performance limits, themes and backup/recovery remain available. Advanced tools retain link diagnosis and adapter panels. Double-clicking devices retains details/management behavior; duplicate open detail windows are prevented.

## Layout and data protection

Nine primary sidebar destinations, a global device/IP/notes search (Enter opens matching devices), real monitoring status, alerts shortcut, settings shortcut and consistent vector icons. Light/dark themes persist. Scrollable forms/cards support 980×650 laptop layouts and maximized windows. New tasks use existing bounded telemetry/speed workers or the separate four-worker discovery pool. No feature creates fake live measurements. Empty connections say Not configured/Unavailable.

First v0.5.0 startup saves a one-time SQLite snapshot under the data folder's backups/before-noc-0.5.0.sqlite3 before opening the redesigned GUI. No database schema change is made. Back up the complete data folder separately to include DPAPI credential/licence/mobile sidecars. Discovery creates a separate pre-import snapshot. Existing restore and retention behavior is preserved. Alignment sessions/settings are bounded; no continuous video or additional automatic speed tests are introduced.

## Verification and limits

Qt integration tests exercise all primary routes, global search, light/dark preferences, 980×650 geometry, empty/read/stale cards, independent cancellation/queuing, bounded background scanning and UI heartbeat, progress/filter/DNS fixtures, multi-selection import/backup/dedup/scope checks, alignment evidence/pause/save, topology/last-hop evidence, duplicate detail windows, metric validation and startup snapshots. Full legacy regressions and Windows frozen/installer tests are required before delivery. Simulated devices and mocked network replies are test-only; they are never placed in the application database shipped to the user.

Real seven-modem paths, Rocket firmware/OIDs, Windows laptop performance, PTR availability, audio hardware and physical dish movements still require field tests. Correct Windows routes/interfaces are necessary for independent WAN tests; ping IP alone does not select a modem. The existing upload test still needs an authorized acknowledging receiver. Cloudflare download preset is bounded throughput, not an Ookla full capacity test. DNS/MAC/vendor fields may be unavailable. Graphs use the latest 240 retained samples; retention can remove older history. Scan cancellation allows in-flight calls to complete. Alignment keeps the latest 600 session samples and one saved result per device. The route schematic does not automatically load Lahore/Sargodha geographic roads.

## Rollback

Close Network Monitor, preserve the full current data folder, and reinstall v0.4.18 if needed. Schema remains compatible. Old GUI ignores new discovery/alignment/UI settings. Use the pre-NOC SQLite snapshot only through existing Restore if reverting saved configuration is necessary; credentials/licence/mobile files remain separate. Admin/issuer records and activation protection were not removed.
