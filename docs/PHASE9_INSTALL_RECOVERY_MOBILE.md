# Phase 9 — Windows installation, recovery and secure mobile access (v0.4.15)

## Delivered behavior

- Separate per-user **Zee Admin Studio Setup** with desktop and Start Menu shortcuts. The monitor and owner panel are separate installations. Neither needs customer-side Python. Installer retains local owner/customer data on uninstall.
- Signed licence import validates issuer signature, PC, expiry and pinned customer profile before touching current activation. A valid previous grant is saved as `license.previous.json`. **Recover previous valid licence** revalidates it; expired, foreign-PC or foreign-profile grants cannot recover activation. Atomic writes flush to disk and clean temporary files on failure. Deactivate removes both local copies; offline deletion cannot revoke other copies.
- Restore preflight checks SQLite integrity, supported schema and configuration JSON/model validity before replacing the live database. Previous database remains `before-restore.bak`. Database-only recovery leaves licence, credentials and mobile files alone.
- Mobile HTTPS page uses customer app name and watermark, escaped as text. Certificate/key partial state fails closed instead of silently changing trust. New identity creation protects its private key before writing the certificate; temporary plaintext key is removed after TLS loading. Not-yet-valid, expired or different-IP certificates fail.
- Phone pairing codes last five minutes and are single use. Hashed session tokens last 30 days, survive service restart, and can be revoked individually/all. Pairing state is validated and bounded to 64 phones/64 KiB; expired tokens are pruned on load/new pairing. Attempts are limited to five per source IP/minute and the rate table is bounded. A failed pairing save returns an error without issuing a session or consuming the code. Stop is safe before start and safe to repeat, and discards the current code.
- Mobile POST requests require the listener's actual host/port and matching browser Origin when supplied. Secure, HttpOnly, SameSite cookies and read-only authenticated snapshots remain in place. Dashboard service is opt-in and must be explicitly started after desktop restart. LAN/VPN routing and phone certificate trust are supplied by the operator.

## Automated acceptance and evidence

`tests/test_phase9_acceptance.py` covers valid recovery, deactivation, tampering, wrong machine/profile, expiry, oversized documents, boolean version rejection, simulated disk failure, certificate partial/protection failure, stable fingerprints, malformed pairing state, real certificate-verified HTTPS pairing, restart, escaped branding, forged Host/Origin, request throttling and malformed configuration backup preservation. Existing full regression suite covers package ceilings, owner encrypted recovery, DPAPI, migrations, customer GUI and network services.

Windows Actions runs on **Windows Server 2022**. The native workflow tests monitor and Studio setup install/shortcuts/frozen launch/same-version reinstall/uninstall. `scripts/verify_customer_build.py` builds a disposable signed customer installer/portable, exercises activation through the import service, observes frozen permissions/branding, reinstalls preserving real encrypted DPAPI credentials/licence/configuration, restores a queued backup with safety copy, and uninstalls preserving data. Deleted public issuer/profile resources fail closed. Its test-only private signing key stays in memory; disposable customer packages are not uploaded. Reports are included with setup artifacts and workflow diagnostics.

**Scope limits:** same-version reinstall validates the installer upgrade path; a released older binary to v0.4.15 is not a native cross-release acceptance test. Schema migration tests are separate. Smoke tests bypass the interactive activation prompt to inspect locked/activated state; they do not automate typing into the Windows GUI. Physical Windows 10/11, actual phone browser/trust import, VPN, seven independent modems, Rocket firmware and old laptop load are unverified. Linux tests mock certificate DPAPI only; production has no plaintext fallback. No hosted relay, automatic Internet key revocation, trusted offline clock, automatic download service or Authenticode certificate is included. Offline expiry uses the PC clock. Installer security warnings can remain on unsigned builds.

## Easy owner/customer test

1. Download the **Studio Setup** artifact, Extract All and run its setup EXE. Open Zee Admin Studio from the shortcut; create a local owner account. Existing issuer: import encrypted recovery before creating any replacement key. Never send keys/passwords to customers or GitHub.
2. Monitor public Setup is an owner evaluation preview. For commercial activation, owner uses Builds / releases with the existing signed customer profile and reviewed build toolchain. Keep profile ID stable for updates to the same customer installation. Only the owner build process needs Python/compiler.
3. On the customer laptop export activation request, issue/import the matching signed licence, restart and check visible features/device cap. Renew once, then use Recover previous valid licence and restart; confirm an expired/wrong-PC file is rejected without replacing activation.
4. Back up database, change a disposable device, restore/relaunch and confirm configuration plus safety copy. Before reinstall/uninstall copy the full data folder and encrypted issuer recovery separately. Database backup does not contain DPAPI credentials or licences. Same Windows account/PC is needed to decrypt saved credentials.
5. For phone testing use a specific reachable PC LAN or configured VPN IP. Enable HTTPS, compare certificate SHA-256, trust that certificate on your own phone, open the shown URL and pair using a fresh code. Confirm a second phone, selective revocation, restart, expiry and logout. Never accept an unexpected certificate identity. Stop before changing IP or resetting certificate; reset revokes all phones.
6. Native reinstall should keep configuration/licence/credential files. Uninstall should remove executable/shortcuts and preserve data. Report OS, package version, error text and the failing step; do not send credentials, signing keys or pairing codes.

## Performance, rollback and next phase

Desktop polling/concurrency behavior is unchanged. Pairing adds bounded small-file validation; HTTPS remains at eight worker threads with five-second socket timeouts, snapshot refresh every five seconds. Snapshot dashboard requires the PC/app to stay online; displayed stale values are labelled. Existing synthetic scheduling/UI benchmark remains part of CI, not a substitute for laptop measurements.

Baseline rollback is **v0.4.14**, commit `b890bb63d12aef75dd20ea9b4b6c6358cc3e5fa2`. Customer schema stays 4 and Studio schema stays 1. Close both apps, copy complete data folders, reinstall the reviewed previous package with the same customer profile ID/issuer. Restore the pre-change copy if needed; protect encrypted credentials under the same Windows account. Previous licence recovery is optional and does not create new entitlements. Old mobile HTML does not carry v0.4.15 branding; stop remote access during rollback if certificate state is inconsistent.

**Phase 10 proposal, awaiting user instruction:** controlled pilot on the user's actual Windows laptop/network: tower/radio layout, five subnet routing, seven independently verified modem paths and traffic/speed, buzzer/disconnect/recovery incidents, mobile LAN/VPN pairing, install/upgrade/backup/uninstall, RAM/CPU/log cleanup. Record real evidence and repair any observed failures before declaring field readiness. Phase 9 automation does not certify this hardware pilot.
